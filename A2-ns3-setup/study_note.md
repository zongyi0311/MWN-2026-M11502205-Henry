## Simple scenario source and run command (built-in ns-3 model)

Source code:

- [`a2-traffic-model.cc`](src/a2-traffic-model.cc)

The scenario uses ns-3's built-in `ThreeGppHttpClient` and
`ThreeGppHttpServer`. It contains two nodes connected by a 100 Mbps
point-to-point link with 10 ms delay. Node 0 behaves as an HTTP client and
Node 1 behaves as an HTTP server. The simulation runs for 60 seconds.

```bash

```

## Built-in traffic model

The built-in model simulates web browsing traffic. A client requests a main
object, receives embedded objects, waits for a reading time, and repeats the
process. Object sizes, number of embedded objects, parsing time, and reading
time are generated by `ThreeGppHttpVariables`. The run records received
packet sizes and inter-arrival times in `built_in_packet_samples.csv`, and
page-level load time and bytes in `built_in_pages.csv`.

### Relation to 3GPP TR 26.926

The assignment calls it TS 26.926, but the referenced document is a 3GPP
Technical Report (TR 26.926), *Traffic Models and Quality Evaluation Methods
for Media and XR Services in 5G Systems*. The report describes trace-based
models and emphasizes packet-size and packet-latency distributions. Its cloud
gaming example describes bursty traffic, commonly using 1500-byte packets,
an inter-burst period related to the frame rate, and a truncated-Gaussian burst
length. The selected ns-3 built-in model is an HTTP traffic model based on
legacy 3GPP-style traffic references. It is not claimed to be a complete
Media/XR implementation of TR 26.926; this limitation is explicitly reported.

Reference: [ETSI/3GPP TR 26.926 V18.2.0](https://www.etsi.org/deliver/etsi_tr/126900_126999/126926/18.02.00_60/tr_126926v180200p.pdf).

## Build/runtime issues encountered

1. The first custom prototype used `EventId::IsRunning()`, which does not exist
   in ns-3.46.1; it was changed to `EventId::IsPending()`.
2. The first run used an output directory that did not exist, so PCAP creation
   failed. Creating `results/` fixed it.
3. The final submission uses only the built-in `ThreeGppHttpClient/Server`
   model; the earlier custom generator was removed from the submission files.
